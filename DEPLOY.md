# HDR Keel: Cloudflare Pages deploy

Deploy destination: **Cloudflare Pages**, project connected to repo `ewlpsuk/hdr-keel-web`
(branch `main`). This mirrors the pattern used for `ewlpsuk/hdr-compass-web`.

## Project settings (set in the Pages dashboard)

| Setting | Value |
|---|---|
| Build command | `npm ci && npm run build` |
| Build output directory | `out` |
| Node.js version | **20** (pinned via `package.json` `engines` and `.node-version`) |
| Build environment variable | `NEXT_PUBLIC_BOOKING_URL` (optional; falls back to the committed default HDR Keel slot) |
| Build environment variable | `NEXT_PUBLIC_PRODUCT_URL` (optional; defaults to `https://hdrcompass.co.uk`) |

## Why `npm ci` and why output `out`

- The static export is generated by `npm run build` using `output: "export"`, which
  writes the site to `out/`. Cloudflare Pages must serve `out` as the output directory.
- Use `npm ci` (not `npm install`) in the build so the build is reproducible from the
  lockfile and never caches a stale `node_modules`. A cached or corrupt `node_modules`
  will fail the build.

## Security headers

Delivered by `public/_headers` (copied into `out/_headers`), which Cloudflare Pages
honours. Includes HSTS, CSP, X-Frame-Options, X-Content-Type-Options and Referrer-Policy.
The `async headers()` block in `next.config.ts` is dead config under `output: "export"`
and can be ignored or removed.

## Post-deploy verification

1. All six routes return HTTP 200 with a trailing slash: `/`, `/about/`, `/services/`,
   `/pricing/`, `/hdr-compass/`, `/contact/`.
2. `/sitemap.xml` and `/robots.txt` return 200 and point at `https://hdrkeel.co.uk`.
3. The booking CTA resolves to the live HDR Keel calendar slot.
4. Lighthouse home-page score is healthy.

## Not checked in

- No wrangler.toml is needed: Cloudflare Pages config lives in the dashboard for this
  project. The two key settings above (build command and output dir) are the ones that
  must be correct or the live DNS will serve a broken site.
